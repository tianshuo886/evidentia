## 1. 为什么“适配”首先是部署问题 <a id='s1'></a>

> *论文的入口不是一个抽象的压缩率，而是同一基础模型要服务多个下游任务时，完整复制参数会让存储、显存与在线切换变得不可承受。*

作者先把全量微调写成对每个任务都学习一个与基础模型同量级的参数增量。GPT-3 175B 让这个代价从“麻烦”变成部署问题：任务越多，越难保存和切换独立实例。论文随后比较两条既有路线的结构性代价：adapter 增加串行层，prefix 类方法占用输入序列长度且优化并不稳定。 〔p.1, p.2, p.3〕

### 表 1：GPT-2 medium 上单次前向的延迟。

![表 1：GPT-2 medium 上单次前向的延迟。](assets/figures/crop_T01_p4_801x849.png)

在 batch=1、sequence=128 的在线情境中，AdapterH 与 AdapterL 相对 Fine-Tune/LoRA 的慢化分别达到 30.3% 和 20.7%；这解释了为何“参数少”不自动意味着“部署快”。 〔T01, p.3〕

## 2. 从任务增量到低秩重参数化 <a id='s2'></a>

> *LoRA 的方法动作很窄却承担了整篇论文的桥梁：不改基础权重本身，而把任务变化限制在一个低秩子空间里。*

在条件语言建模目标中，作者把原本直接优化的 ΔΦ 改写为由更小参数 Θ 编码的增量。对任意 dense weight W0，LoRA 取 ΔW=BA，其中 A 与 B 的秩 r 远小于矩阵维度；训练期间 W0 不接收梯度，只训练 A、B。A 用高斯随机初始化、B 置零，因此一开始 BA=0，随后用 α/r 缩放更新。 〔p.2, p.4, F01〕

### 图 1：LoRA 的重参数化。

![图 1：LoRA 的重参数化。](assets/figures/crop_F01_p1_151x153.png)

图示把冻结的预训练权重路径与只训练 A、B 的低秩旁路并列，前向输出相加；它具体化了 ΔW=BA 的计算位置。 〔F01, p.4〕

## 3. 把低秩更新放进 Transformer，并折叠回部署图 <a id='s3'></a>

> *论文把 LoRA 的普适 dense-layer 原则收窄到可测的 Transformer attention 配置，再利用矩阵可合并性获得部署收益。*

在 Transformer 中，作者把研究范围限定为 self-attention 的权重，主实验主要适配 Wq 与 Wv，冻结 MLP；Wk、Wo、LayerNorm 与 bias 的系统组合不在这篇论文的实证范围内。训练结束后可显式计算 W=W0+BA 并像普通模型一样推理，因此没有额外 adapter 层深度。代价是若把不同任务的 BA 都吸收到 W 中，同一 batch 里混合任务的模块切换不再直接。 〔p.4, p.5〕

这个设计使“训练时只存小增量”和“推理时不加层”形成一条连贯链条，但不能把它简化为所有参数都低秩更新。论文报告 GPT-3 训练显存可从约 1.2 TB 降至 350 GB，r=4 且只适配 query/value 时 checkpoint 约由 350 GB 变为 35 MB；这些数字描述的是特定规模与配置。 〔p.4〕

贡献的边界与贡献本身同样重要：attention-only 与可合并部署是本文测得的具体选择，不是无条件的模型改造承诺。 〔p.4, p.5〕

## 4. 跨模型实证：少量参数能否保住任务质量 <a id='s4'></a>

> *实证章节按模型规模逐步放大：先看 GLUE，再看生成任务，最后把方法推到 GPT-3 175B，从而同时检验参数效率与质量保持。*

在 RoBERTa、DeBERTa、GPT-2 和 GPT-3 上，LoRA 与 full fine-tuning、adapter、prefix tuning、bias-only 等方法比较。GLUE 表显示 RoBERTa-base 的 LoRA 只训练约 0.3M 参数而平均分 87.2，DeBERTa-XXL 用约 4.7M 参数达到 91.3；GPT-2 的 E2E NLG 以及 GPT-3 的 WikiSQL、MultiNLI-m、SAMSum 则把比较推进到生成与超大模型。 〔T02, T03, p.6〕

## 5. rank 与矩阵位置：效率来自哪里 <a id='s5'></a>

> *作者把“为什么少量参数有效”拆成两个可操作变量：在哪些 attention 矩阵上适配，以及低秩 r 取多大。*

相同参数预算下，Wq 与 Wv 同时适配通常优于只适配一种矩阵，说明参数位置比总量本身更关键。rank 消融显示，许多任务在很小 r 时就接近较高 rank；但结果并非单调，GPT-2 E2E 的不同 rank 仍有指标差异，且表 18 明确部分超参在 r=4 上调过。 〔T05, T06, T08, T18, p.10, p.17, p.26〕

## 6. 子空间证据提供的机制线索 <a id='s6'></a>

> *最后一组实验不再问“分数是多少”，而是问低秩更新是否在重复选择有结构的方向，以及这些方向与原模型有什么关系。*

不同随机种子的 LoRA 模块在若干层显示相似的列向量子空间，且 ΔW 与 Wq 的投影相对随机矩阵基线更大。作者据此提出一种解释：更新可能放大预训练模型中与下游任务相关、却没有被充分强调的方向。rank 增大时又会吸收更多 Wq 已强调的方向。 〔F05, F06, F07, F08, T07, p.12, p.17, p.25, p.26〕

## 7. 结论的有效范围与尚未回答的问题 <a id='s7'></a>

> *LoRA 的实证贡献清晰，但它的可解释性、普适性与系统部署边界都应随结论一起读。*

这篇论文有力支持的命题是：在其测试的 Transformer 语言模型、下游任务和 attention 配置中，冻结基础模型并学习低秩增量可以大幅减少可训练/存储参数，同时保持接近全量微调的质量，并在合并权重后避免额外推理层。它没有系统解决 MLP、LayerNorm、bias 组合，也没有证明跨语言、困难任务或分布偏移下仍只需极低 rank。 〔p.4, p.5, p.26〕

子空间和 rank 实验证据让“低 intrinsic rank”成为可信的解释方向，但不排除优化便利性、任务特定方向或超参选择等替代解释。部署上，合并权重有利于单任务推理，却让不同任务模块在同一 batch 的灵活切换变得不直接；因此论文的贡献应读成一个有明确工程取舍的、证据支持范围内的适配方案。 〔p.4, T07, F07, F08〕

读者最终应保留一个带边界的判断：LoRA 把适配增量压到低秩结构中，在多组语言模型实验里表现出强参数效率；其普适性与机制因果仍开放。 〔p.4, p.5, p.26〕
